# Finding: EMPULSE L4 AGA exposes NATS and a separate TCP/60000 channel

> **Scope:** EMPULSE-specific packet observation; cross-game architectural role remains unresolved.

**Date:** 3 September 2026  
**Confidence:** High for transport identification; Medium for application role  
**Session:** EMPULSE ranked/practice capture

## Observation

`api-l4-aga-prod.maverick-global.prod.1047games.com` is contacted on two distinct long-lived TCP paths during the Ranked attempt.

The first path uses TCP/4222. The first server application payload is readable NATS `INFO` data identifying NATS 2.12.6, server `nats-prod-2`, cluster `nats-prod`, authentication requirements, TLS requirements and JetStream capability. A TLS ClientHello follows on the same TCP connection.

The second path uses TCP/60000 and carries opaque binary records. The first observed record begins with a four-byte little-endian length followed by non-text data; no application protocol was identified.

## Correlation

The NATS path is active before the Orion log records `ReportServerSessionManager` data. Both L4 paths persist independently of the standalone practice world.

## Interpretation

The L4 endpoint is therefore better treated as a persistent broker/control/session subsystem than as an ordinary HTTPS API.

The evidence does **not** establish that NATS itself, TCP/60000, or the hostname as a whole is the final gameplay allocator. The allocator/session-broker boundary remains unresolved.

## Why it matters

A future successful EMPULSE match should capture the exact control-plane transition immediately before `SERVER READY` and correlate it against NATS/60000 traffic. NATS subjects and TCP/60000 message semantics are now concrete protocol-level targets.
