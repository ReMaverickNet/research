# Repository navigation

`research` is the evidence and source-of-truth repository. Read from the root down: central maps first, then findings and session records, then detailed evidence and raw/derived material.

## Start here

- [Network architecture](../NETWORK.md)
- [Build tracks](../BUILD_TRACKS.md)
- [Research roadmap](roadmap.md)
- [Centralisation direction](centralisation.md)

## Main areas

| Path | Purpose |
|---|---|
| `findings/` | Small, evidence-backed conclusions |
| `sessions/` | Reproducible experiments and annotations |
| `networking/` | Network-specific evidence and protocol notes |
| `logs/` | Sanitised logs and derived extracts |
| `captures/` | Capture metadata and analysis artefacts |
| `builds/` | Build, depot, manifest and hash metadata |
| `redkard/` | Anti-cheat architecture and compatibility observations |
| `reverse-engineering/` | Static-analysis and Unreal-oriented research |
| `tooling/` | Capture, parsing and analysis helpers |
| `archive/` | Preserved analysed session bundles |
| `docs/` | Guides, methodology and project-wide documentation |

## Reading rule

Prefer a finding or session record before opening the underlying evidence. Findings should identify the evidence they rely on and distinguish observation, inference and unknowns.

## Future wiki

Once the dataset is mature, the human-facing architecture and reference material can move into a wiki. The repository should continue to preserve the evidence, provenance and reproducible source material behind that reference.
