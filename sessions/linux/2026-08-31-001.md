## Observations

### Build and runtime

The client identifies itself as `PortalWars2-CL-600100`, game version `0.3.1.0 (9)`, Net CL `591413`, on Unreal Engine 5.5.4.

### Live-service / backend state

Several online-service requests returned failures or unavailable data during startup and menu use. A localization manifest request reported `LOCALIZATION_MANIFEST_NOT_FOUND`, and a cloud-save request returned HTTP 401. These failures provide context for dead or partially functional menu features, but the Battle Pass request itself was not identified by name in the UE log.

### Locker and badge UI

`WBP_PlayerCard_C:UpdateBadges` repeatedly attempted to access `Textures[0]`, `Textures[1]`, and `Textures[2]` while `Textures` had length 0. Empty async-load requests occurred in the same sequence.

### Loadout and attachments

The capture repeatedly logged invalid/default loadout-slot handling and quickbar selection of slot `None`. The player was using the AER SMG (Sprinter / Aeros SMG) and had applied an extended barrel and recoil grip. The log nevertheless records attachment failures such as `TargetComponent Not Found` for `AttachID_AER_SMG_ExtBarrel` and `AttachID_AER_SMG_RecoilGrip`. The player reported that the Sprinter continued to function normally in-game, so these messages should not currently be interpreted as proof of a hard weapon failure.

The burst pistol was also present in the session. Its `AttachID_MER_BurstPistol_ImpactBullets` attachment produced an invalid-class/override warning even though the pistol was not manually edited during the test.

### Practice range

The game browsed to `/MAP_Training/TrainingGrounds_Main?Variant=PortalWarsGameVariant:GV_PracticeRange_Default`.

The game feature `MOD_PracticeRange` was activated during startup. Practice dummies use the `BP_PracticeDummy_C` class and generate `GF1047HealthComponent` death events when killed.

### Portals

The PortaPortal sequence produced Gameplay Cue activity under `/EQP_AER_PortaPortal/`, including fire, create and destroy cues. The normal portal produced `GCN_FirePortal`, `GCN_FirePortal_Outcome`, `GCNL_FirePortalLauncher`, `GCNL_Portal_Teleport_Character`, and `GCN_Portal_Teleport` cues.

### Anti-cheat

The Proton trace shows `anticheat.x64.redkard.exe`, `RedKard.sys`, and `client.x64.redkard.dll` being loaded. However, the RedKard driver/service path also produces `Unhandled exception code c0000409` while loading `RedKard.sys`, followed by Wine service-pipe errors. Separately, EOS reports `[AntiCheatClient] Anti-cheat client not available. Verify that the game was started using the anti-cheat bootstrapper if you intend to use it.`

The EOS anti-cheat warning occurs during early startup, before the practice-range feature is activated. Therefore, this capture does not support the hypothesis that the practice range itself causes the EOS anti-cheat-unavailable state. The stronger current hypothesis is that the anti-cheat bootstrap/driver/service integration is incomplete or incompatible under this Proton environment.

Merlin subsequently reports receiving data from `ReportServerSessionManager`, so the client-side Merlin component was not simply absent or completely inactive.

### Shutdown

Exiting the practice range browsed back to `/Game/Maps/MainMenu/MainMenu?closed`, reported `Connection failed; returning to Entry`, unloaded the training world, and then the game shut down normally.
