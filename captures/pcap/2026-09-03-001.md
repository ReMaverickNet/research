## Correlation method

The authoritative-session table uses `SERVER READY` timestamps as the primary join key. For each overlapping capture, the filtered PCAP was checked for packets to the logged authoritative host on **any transport port**, then specifically to the logged `SERVER READY` UDP port. Both checks returned zero packets for the correlated sessions.

This is an observation about the **filtered files**. The private raw wide captures were not included in the contributor bundle, so the analysis cannot prove whether the original wide files contained and the later filter removed those flows.

## Filtering assessment

The five exports contain substantial TCP/UDP traffic on port 443 plus DNS/broadcast/multicast and other background traffic. The three capture windows that overlap authoritative sessions contain no packet bearing on the corresponding log-reported game-server hosts, despite the logs showing successful `Browse`, `SendInitialJoin` and server-welcome transitions.

The correct conclusion is therefore **“the filtered exports are unsuitable for gameplay-flow reconstruction”**, not **“the original captures contained no gameplay traffic.”**
